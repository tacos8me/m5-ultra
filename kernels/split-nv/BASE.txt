Base image: lmsysorg/sglang:dev-dsv41@sha256:4a5d132a06a77c8331e15845f2e925adc788b00105097ad55409afa3f4fa4860
  (torch 2.13.0+cu130, flashinfer 0.6.18+cu130 git 69ff11fc). The Dockerfile applies two patches:

sglang-dsv41-split.patch: applies to /sgl-workspace/sglang/python and yields the tested SGLang tree: the
  DeepSeek-V4.1 serving port (SM120 kernels, pinned Engram, launch fusion, long-context indexer) plus the split hooks
  (prompt-state capture, deterministic top-k ties). The build checks every resulting file against TREE.sha256
  (4,784 files, .so and __pycache__ excluded) and fails on any difference.

flashinfer-sparse-mla-sm120.patch: FlashInfer's SM120 sparse-MLA prefill only instantiated extra_page_block_size 64
  and 2; V4.1's compressed layers need 128 and 256 (the decode kernel already takes it at runtime). The patch adds
  those dispatch cases, no kernel logic changes. The image ships an AOT .so that shadows the sources, so the build
  recompiles it (sm_120f, -O3, ~30 s, no GPU needed). Its SASS is identical to the production library's.
